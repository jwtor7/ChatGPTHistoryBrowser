# ChatGPT Export Browser Product Specification

- Status: Baseline
- Architecture: [ADR-0001](../docs/adr/0001-local-desktop-architecture.md)
- Implementation sequence: [Implementation Plan](../docs/IMPLEMENTATION_PLAN.md)

## 1. Purpose

The product is a local desktop application for browsing, searching, and recovering content from an extracted official ChatGPT data export.

It avoids the generated HTML archive, which can be too large for a browser to load. Conversation JSON shards are the authoritative conversation source. The application creates a disposable local SQLite search index outside the source export.

The application is privacy-sensitive infrastructure. A feature is incomplete if it works functionally but can expose private content, mutate the source, escape the selected directory, execute archived content, or contact an external service.

## 2. Requirement language

`SHALL` and `SHALL NOT` define mandatory release requirements.

Requirements use EARS forms:

- **Ubiquitous:** The system shall ...
- **Event-driven:** When ..., the system shall ...
- **State-driven:** While ..., the system shall ...
- **Unwanted behavior:** If ..., then the system shall ...
- **Optional feature:** Where ..., the system shall ...

## 3. Users and goals

### Primary user

A person who has extracted their own ChatGPT data export and wants to find or recover conversations and attachments locally.

### User goals

- Select an extracted export without technical setup.
- Confirm whether the directory is supported.
- Browse and search a large history.
- Understand message roles and alternate branches.
- Preview or recover attachments safely.
- Stop, resume, rebuild, or delete indexing.
- Know where derived private data is stored.
- Trust that the source remains unchanged and nothing is uploaded.

## 4. Scope

### In scope

- macOS, Windows, and Linux desktop applications.
- Extracted export directories.
- `conversations.json` and numbered `conversations-*.json` shards.
- Conversation mapping trees and `current_node`.
- Title and message full-text search.
- Date, role, archived, starred, and attachment filters when source fields exist.
- Safe local previews for required image, audio, video, PDF, text, source, CSV, and JSON formats.
- Safe fallback for unsupported attachments.
- Disposable local SQLite and FTS5 indexes.
- Independently generated synthetic fixtures and benchmarks.

### Out of scope for the first release

- Importing ZIP archives directly.
- Parsing the generated HTML archive as conversation content.
- Modifying, repairing, or normalizing the source export.
- Editing conversations.
- Cloud sync, account login, telemetry, analytics, or remote search.
- Automatic updates.
- Mobile or hosted-web deployment.
- Guaranteed playback of codecs unsupported by the operating-system WebView.
- Guaranteed recovery of missing source files.
- Guaranteed detection or removal of all personal information.
- Remembering the selected absolute export path across application restarts.

## 5. Trust and data boundaries

### Trusted

- Application code and bundled static assets.
- Bundled SQLite and schema migrations.
- Synthetic fixtures generated by this repository.
- Opaque identifiers and cryptographic random values created by the application.

### Untrusted

- Every file, filename, path component, symlink, identifier, timestamp, role, MIME value, title, message, Markdown fragment, mapping edge, and attachment metadata value in an export.
- Every request received by the loopback listener until authorization and origin checks pass.
- Every FTS query string until it passes the application's constrained parser.
- Every external application used to open an unsupported attachment.

### Derived private data

The SQLite database, FTS indexes, WAL files, staging generations, thumbnails, and any user-requested recovered copies may contain private information. They are local, disposable, and protected only by operating-system account permissions and any disk encryption the user has enabled.

## 6. Architectural invariants

1. The source export is opened read-only.
2. No cache or index is created in the source export or repository.
3. The backend never returns an absolute filesystem path to the renderer; a manually entered path is transient request input only.
4. Conversation content comes from JSON shards, not generated HTML.
5. The application opens no non-loopback network connection during normal operation.
6. The server binds only to `127.0.0.1` on an operating-system-assigned port.
7. The random port is never treated as authentication.
8. Every private API request is authorized.
9. Every attachment request is root-contained and fail-closed.
10. Export HTML, scripts, SVG, and unknown active formats never execute in the renderer.
11. Partial indexing never replaces a completed shard generation.
12. Application logs contain codes, counts, durations, and application-owned opaque IDs only.
13. Public repository artifacts use synthetic content only.

## 8. Bounded-resource defaults

Limits are defensive defaults and may be tuned from synthetic benchmark evidence. Any increase requires security tests.

| Resource                          |                                 Default maximum |
| --------------------------------- | ----------------------------------------------: |
| API JSON request body             |                                          64 KiB |
| Search query text                 |                       512 Unicode scalar values |
| Conversation list page            |                                        100 rows |
| Search result page                |                                        100 rows |
| Conversation message page         |                                    100 messages |
| Non-media API response            |                                           2 MiB |
| JSON nesting depth                |                                             128 |
| One JSON string                   |                                          64 MiB |
| One conversation record           |                                         256 MiB |
| Mapping nodes in one conversation |                                         250,000 |
| Reconstructed active-path nodes   |                                         250,000 |
| Text preview                      |                                           1 MiB |
| Media Range response              |                                           1 MiB |
| Inline image decoded dimensions   |                                   50 megapixels |
| Inline PDF source size            |                                         100 MiB |
| Diagnostic message                | 512 characters from application-owned text only |

Exceeding a preview limit does not make the source attachment invalid. The application provides a safe copy or external-open fallback.

## 9. Measurable nonfunctional requirements

### 9.1 Reference environment

Performance release tests use:

- a current supported macOS, Windows, or Linux release;
- at least 4 physical or 8 logical CPU cores;
- 8 GB RAM;
- local SSD storage;
- a production build; and
- no unrelated CPU- or disk-intensive workload.

Results are recorded separately for each platform. Synthetic data and generated filenames are used exclusively.

### 9.2 Benchmark profiles

| Profile   | Contents                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------ |
| `small`   | 100 conversations, multiple shards, every branch and attachment error case                                               |
| `scale`   | 10,000 conversations, 10,000 attachment metadata records, at least 500 MB total JSON                                     |
| `media`   | Several gigabytes of generated sparse or synthetic media data with required signatures                                   |
| `hostile` | Malformed JSON, deep nesting, cycles, oversized values, malicious Markdown, MIME conflicts, traversal, and symlink cases |

## 10. API behavior

The wire schema is generated from shared Rust and TypeScript types. These resources define the minimum shape:

| Method and route                                         | Authorization             | Purpose                                                                    |
| -------------------------------------------------------- | ------------------------- | -------------------------------------------------------------------------- |
| `GET /healthz`                                           | Public, no private fields | Process readiness                                                          |
| `GET /api/status`                                        | Bearer                    | Selected-export and aggregate index status                                 |
| `POST /api/export/pick`                                  | Bearer + native user UI   | Open the native folder picker and validate the user-selected directory     |
| `POST /api/export/discard`                               | Bearer                    | Cancel active work, close source handles, and discard the current session  |
| `POST /api/index/start`                                  | Bearer                    | Start or resume indexing                                                   |
| `POST /api/index/cancel`                                 | Bearer                    | Request cooperative cancellation                                           |
| `GET /api/index/status`                                  | Bearer                    | Bounded progress snapshot                                                  |
| `DELETE /api/index`                                      | Bearer                    | Delete derived index and cache                                             |
| `GET /api/conversations`                                 | Bearer                    | `page` and `pageSize` conversation summaries, search, sorting, and filters |
| `GET /api/conversations/{conversation_id}`               | Bearer                    | Bounded active-path and branch data                                        |
| `GET /api/conversations/{conversation_id}/export`        | Bearer                    | Estimate a Markdown, PDF, or text conversation document                    |
| `POST /api/conversations/{conversation_id}/export`       | Bearer + native user UI   | Save a Markdown, PDF, or text conversation document                        |
| `POST /api/conversation-set/export/estimate`             | Bearer + same origin      | Estimate a bounded manual or all-matching conversation document            |

| `POST /api/attachments/{attachment_id}/media-capability` | Bearer                    | Mint session-bound media URL                                               |
| `GET /api/attachments/{attachment_id}/text`              | Bearer                    | Read a bounded escaped-text preview                                        |
| `GET /media/{capability}`                                | Signed capability         | Bounded full or single-range attachment response                           |
| `POST /api/attachments/{attachment_id}/copy`             | Bearer                    | User-approved recovered copy                                               |
| `POST /api/attachments/{attachment_id}/open`             | Bearer                    | User-approved external open                                                |

The renderer polls indexing status with authenticated fetch. It does not use an unauthenticated EventSource.

All identifiers in these routes are application-owned opaque identifiers. Source identifiers and filesystem paths are not URL components.

If the user explicitly enters a directory path, the selection request may contain that path. The server SHALL NOT echo it in the response, log it, place it in a URL, or persist it. A native-picker implementation should keep the selected path entirely in Rust.

## 11. Error model

API errors use one shared envelope:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Application-owned safe message."
  }
}
```

`code` is a stable uppercase identifier and `message` is static application-owned text. Stack traces, SQL, source values, and paths are never returned to the renderer or ordinary logs.

| Code                         | Trigger                                                    | User experience                                        | State and recovery                               |
| ---------------------------- | ---------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------ |
| `SERVER_BIND_FAILED`         | Secure loopback listener cannot start                      | Startup stops with retry and support guidance          | No fallback binding; no private state opened     |
| `AUTH_REQUIRED`              | Missing or invalid bearer or media capability              | Generic session-expired message                        | Reveal no resource existence; restart session    |
| `REQUEST_ORIGIN_REJECTED`    | Unexpected Host or Origin                                  | Generic request denied                                 | Reveal no resource existence                     |
| `EXPORT_NOT_SELECTED`        | Export operation without a selected handle                 | Return to selection action                             | No state change                                  |
| `EXPORT_NO_SHARDS`           | No supported conversation JSON                             | Explain what an extracted export should contain        | Let user choose another directory                |
| `EXPORT_UNREADABLE`          | Root cannot be opened read-only                            | Explain permission/access problem                      | Source unchanged; allow retry                    |
| `SHARD_UNREADABLE`           | One shard cannot be opened or read                         | Mark index partial and identify relative shard ordinal | Other independent shards may continue            |
| `SHARD_MALFORMED`            | Safe parsing of a shard cannot continue                    | Mark shard failed with bounded explanation             | Previous generation remains active               |
| `RECORD_UNSUPPORTED`         | One recoverable record has unsupported structure           | Show warning count, not content                        | Skip record and continue                         |
| `RECORD_LIMIT_EXCEEDED`      | Record, string, depth, or node limit exceeded              | Explain safety limit and compatibility-reporting path  | Skip safely or fail only that shard              |
| `GRAPH_CURRENT_NODE_MISSING` | Active endpoint absent                                     | Show valid recoverable content where possible          | Preserve nodes and branch metadata               |
| `GRAPH_NODE_MISSING`         | Parent or child reference absent                           | Show incomplete-path warning                           | Render valid path segment                        |
| `GRAPH_CYCLE`                | Mapping cycle detected                                     | Show malformed-graph warning                           | Stop traversal at first repeated node            |
| `INDEX_FTS_UNAVAILABLE`      | Bundled database lacks required FTS5                       | Index unavailable message                              | Stop indexing; installation is invalid           |
| `INDEX_SCHEMA_INCOMPATIBLE`  | Index migration cannot safely proceed                      | Offer discard and rebuild                              | Never modify source                              |
| `INDEX_IO_FAILED`            | Derived database cannot be written                         | Explain local storage problem                          | Roll back batch; prior generation remains active |
| `INDEX_CANCELLED`            | User cancellation completes                                | Show paused/cancelled state                            | Completed generations remain usable              |
| `INDEX_RECOVERY_REQUIRED`    | Abandoned staging generation detected                      | Show recovery progress                                 | Remove staging and resume safely                 |
| `CACHE_DELETE_FAILED`        | Some derived cache files remain                            | Explain exact application-owned cache category         | Close handles and allow retry/manual cleanup     |
| `SEARCH_INVALID_QUERY`       | Query exceeds bounds or violates grammar                   | Show safe syntax guidance                              | No SQL executed                                  |
| `CONVERSATION_UNAVAILABLE`   | Opaque conversation no longer belongs to active generation | Refresh list message                                   | Requery current generation                       |
| `ATTACHMENT_NOT_REFERENCED`  | Unknown opaque attachment ID                               | Generic unavailable message                            | Reveal no path or source ID                      |
| `ATTACHMENT_MISSING`         | Metadata exists but local candidate does not               | Inline missing-file explanation                        | Conversation remains usable                      |
| `ATTACHMENT_OUTSIDE_ROOT`    | Traversal, prefix, device path, or symlink escape          | Security denial                                        | Read zero bytes; record code-only security event |
| `ATTACHMENT_TYPE_MISMATCH`   | Signature conflicts with metadata                          | Explain safer handling                                 | Use detected allowlist or download fallback      |
| `ATTACHMENT_UNSUPPORTED`     | No safe inline renderer                                    | Offer copy or external open                            | Serve as attachment only                         |
| `ATTACHMENT_PREVIEW_LIMIT`   | Safe type exceeds inline limit                             | Explain preview limit                                  | Offer copy or external open                      |
| `MEDIA_RANGE_INVALID`        | Unsupported or unsatisfiable Range                         | Browser-compatible range error                         | Read no out-of-range bytes                       |
| `MEDIA_CAPABILITY_EXPIRED`   | Media capability no longer valid                           | Refresh preview action                                 | Mint a new capability after bearer authorization |
| `COPY_DESTINATION_FAILED`    | Recovered copy cannot be created                           | Explain destination failure                            | Source remains unchanged                         |
| `EXTERNAL_OPEN_FAILED`       | OS refuses external-open request                           | Explain fallback                                       | Offer recovered copy                             |

Unknown internal errors map to `INTERNAL_ERROR` with no raw exception text in the UI.

## 12. Given/When/Then acceptance criteria

### AC-001: Secure startup

**Given** a production application launch<br>
**When** the local service starts<br>
**Then** its effective listener address is numeric IPv4 loopback<br>
**And** its port was assigned from a `0` bind<br>
**And** a request without valid authorization retrieves no private response.

### AC-002: No unsafe bind fallback

**Given** the secure listener cannot bind<br>
**When** startup handles the failure<br>
**Then** the application shows `SERVER_BIND_FAILED`<br>
**And** it does not bind to a fixed, wildcard, hostname, LAN, or IPv6-wildcard address.

### AC-003: Valid export selection

**Given** a generated export with two supported shards<br>
**When** the user selects its directory<br>
**Then** validation succeeds without modifying any source path, size, hash, or modification time<br>
**And** the renderer receives no absolute path.

### AC-004: Invalid directory

**Given** a generated directory with no supported shard<br>
**When** the user selects it<br>
**Then** validation returns `EXPORT_NO_SHARDS`<br>
**And** no index is created for it.

### AC-005: Streaming scale

**Given** the generated `scale` profile<br>
**When** initial indexing completes in a production build<br>
**Then** it satisfies NFR-PERF-001 and NFR-PERF-002<br>
**And** no complete shard is present in renderer memory<br>
**And** all completed shards are searchable.

### AC-006: Progress and cancellation

**Given** active indexing<br>
**When** the user requests cancellation<br>
**Then** status changes within NFR-PERF-005<br>
**And** the current incomplete generation is not activated<br>
**And** every previously active shard remains browsable.

### AC-007: Safe resume

**Given** an interrupted indexing run with abandoned staging rows<br>
**When** the application starts indexing again<br>
**Then** it removes or resumes only validated staging state<br>
**And** the final normalized data and search results match an uninterrupted run.

### AC-008: Search and filters

**Given** generated records containing title and message search terms plus all optional filter fields<br>
**When** the user searches and combines date, role, archived, starred, and attachment filters<br>
**Then** only matching conversations appear<br>
**And** results use deterministic `page` and `pageSize` pagination<br>
**And** latency satisfies NFR-PERF-007.

### AC-009: Active path

**Given** a generated mapping tree with a valid `current_node` and alternate children<br>
**When** the conversation opens<br>
**Then** the displayed active path is the reversed parent chain from `current_node`<br>
**And** alternate branch points are available<br>
**And** timestamps do not reorder the mapping path.

### AC-010: Malformed graph

**Given** generated mapping trees containing a missing node and a cycle<br>
**When** each conversation opens<br>
**Then** the valid path portion renders<br>
**And** the corresponding safe warning appears<br>
**And** the UI remains responsive.

### AC-011: Stored-XSS resistance

**Given** generated messages and metadata containing script elements, event handlers, hostile links, and raw HTML<br>
**When** the content renders<br>
**Then** no script or event handler executes<br>
**And** no external request occurs<br>
**And** no privileged renderer API is reachable.

### AC-012: Attachment type detection

**Given** generated `.dat` files whose metadata and signatures include matching and conflicting types<br>
**When** previews are requested<br>
**Then** allowlisted signatures use the correct safe renderer<br>
**And** conflicts show `ATTACHMENT_TYPE_MISMATCH`<br>
**And** active or unknown types never render inline.

### AC-013: Root containment

**Given** generated traversal, alternate-prefix, device-path, and symlink-escape references<br>
**When** any preview, copy, or open action is requested<br>
**Then** every request returns `ATTACHMENT_OUTSIDE_ROOT`<br>
**And** zero bytes outside the selected root are read.

### AC-014: Missing attachment

**Given** generated attachment metadata without a corresponding file<br>
**When** its conversation opens<br>
**Then** the message and remaining conversation render normally<br>
**And** the attachment shows `ATTACHMENT_MISSING`.

### AC-015: Large media

**Given** a generated browser-supported media file larger than the media chunk limit<br>
**When** playback requests byte ranges<br>
**Then** the server returns bounded valid ranges<br>
**And** does not buffer the complete file<br>
**And** invalid ranges return `MEDIA_RANGE_INVALID`.

### AC-016: Index deletion

**Given** a completed index with WAL or staging artifacts<br>
**When** the user confirms index deletion<br>
**Then** the application closes its handles and deletes every derived file for that opaque archive<br>
**And** the source manifest remains unchanged.

### AC-017: Offline runtime

**Given** a production application running the full `small` profile<br>
**When** onboarding, indexing, search, conversation rendering, and previews complete<br>
**Then** network instrumentation records no DNS request and no non-loopback connection.

### AC-018: Redacted diagnostics

**Given** generated content markers planted in titles, messages, filenames, paths, and attachment metadata<br>
**When** success and failure workflows complete<br>
**Then** none of those markers appears in logs, error responses, snapshots, or benchmark reports.

### AC-019: Production packages

**Given** installed production artifacts on macOS, Windows, and Linux<br>
**When** the `small` profile smoke workflow runs<br>
**Then** selection, indexing, search, conversation display, safe image preview, and index deletion succeed.

### AC-020: Public-repository privacy gate

**Given** the complete intended commit and local Git history<br>
**When** automated scanners and the manual privacy checklist run<br>
**Then** no prohibited export artifact, private absolute path, secret, or non-synthetic personal-data value is found<br>
**And** the project stops for explicit approval before the first push.

### AC-021: Selected conversation document

**Given** two generated conversations selected across paginated results<br>
**When** the user exports the selection as Markdown, PDF, or plain text<br>
**Then** the exact conversation, message, omitted-attachment, and byte counts are shown before saving<br>
**And** the document preserves selection and message order without internal identifiers, attachment names, branches, paths, capabilities, logs, or diagnostics<br>
**And** cancelling confirmation or the native dialog creates no file.

### AC-022: Complete filtered conversation document

**Given** a generated filtered result of no more than 100 conversations across multiple pages<br>
**When** the user selects all matching and confirms a document export<br>
**Then** the backend resolves the complete submitted query independent of pagination<br>
**And** changing the query clears the selection visibly<br>
**And** any query, result-order, format, or serialized-document change after estimate returns a conflict before the native save dialog opens.

## 14. Implementation checklist

### Privacy and safety

- [ ] Repository ignore rules and privacy gate exist before private compatibility work.
- [ ] All committed fixtures and screenshots are generated synthetic artifacts.
- [ ] Source immutability is asserted by manifest comparison.
- [ ] Renderer DTOs contain no absolute paths.
- [ ] Logs and errors pass planted-marker tests.
- [ ] Runtime network deny tests pass.

### Transport

- [ ] Axum uses a pre-bound `127.0.0.1:0` socket.
- [ ] Per-launch bearer authorization has at least 256 bits of entropy.
- [ ] Bootstrap fragment is removed and not persisted.
- [ ] Private routes enforce authorization, Host, Origin, method, and body limits.
- [ ] Media URLs are opaque, signed, session-bound, and renewable.
- [ ] CSP and Tauri navigation policies are verified in production.

### Data and indexing

- [ ] Shards are streamed and hashed.
- [ ] Database migrations are versioned.
- [ ] Staged generations activate atomically.
- [ ] FTS5 title and message indexes remain consistent.
- [ ] Search and filter SQL is parameterized.
- [ ] Cancellation, crash recovery, rebuild, and delete are tested.

### Conversation UI

- [ ] Lists and messages are paginated or virtualized.
- [ ] Active paths and branches are correct.
- [ ] Roles are distinct and unknown roles degrade safely.
- [ ] Markdown and code render without raw HTML.
- [ ] Malformed and partial records have understandable states.
- [ ] Primary flows pass keyboard and accessibility checks.

### Attachments

- [ ] Identifier matching handles both supported `.dat` naming styles.
- [ ] Root-contained resolution passes the cross-platform escape corpus.
- [ ] Signature policy covers every required preview and mismatch.
- [ ] PDF.js is local and scripting/network-disabled.
- [ ] Text and media buffers obey limits.
- [ ] Copy and external open require explicit action and never use a shell.

### Release evidence

- [ ] Unit, integration, security, end-to-end, production, and performance tests pass.
- [ ] Native packages are installed and smoke-tested on all three operating systems.
- [ ] Documentation includes privacy, cache, `.dat`, troubleshooting, and safe-reporting guidance.
- [ ] Dependency audit, license inventory, and SBOM are complete.
- [ ] Complete diff, untracked files, tracked files, and Git history pass privacy review.
- [ ] Exact intended publication files and audit commands are reported.
- [ ] Explicit approval is requested before the first push.

## 15. Release blockers

Any of the following blocks release:

- a source-export write or metadata change;
- private or real export content in the repository, Git history, logs, screenshots, tests, or reports;
- a listener reachable outside numeric IPv4 loopback;
- an unauthenticated private response;
- a non-loopback runtime request;
- stored script execution or raw export HTML rendering;
- a path or symlink escape;
- shell execution based on export content;
- whole-archive or whole-shard buffering;
- partial-generation activation;
- missing production-build tests;
- failure of the scale, security, or privacy gates; or
- a first push attempted without explicit approval.
